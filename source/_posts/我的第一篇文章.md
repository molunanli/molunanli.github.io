作为一个没有服务器、也不想花钱的人，拥有一方属于自己的写作天地，听起来好像有点难？其实不然。在尝试了各种方案后，我最终选择了 **Hexo + GitHub Pages** 这对经典组合——完全免费，并且拥有极高的自由度。

这篇文章就是我搭建全过程的心得，踩过的坑和解决方法都在里面了，希望能帮到想要开始写博客的你。

## 为什么选择 Hexo + GitHub Pages？

-   **完全免费**：不需要买服务器或虚拟主机，GitHub Pages 提供无限流量和空间（只要不滥用）。
-   **静态网站，速度飞快**：Hexo 生成的是纯 HTML/CSS/JS 文件，配合 CDN 访问非常快。
-   **写作体验纯粹**：用 Markdown 写文章，然后一条命令就能部署，让我能专注于内容本身。
-   **版本控制**：所有文章和配置都托管在 GitHub 上，再也不怕丢文件了。

## 整个过程分为四大步

1.  本地安装环境
2.  初始化博客并选择主题
3.  推到 GitHub 仓库
4.  开启 GitHub Pages 并自动部署

下面我一个一个说，并会重点标注我踩过的坑。

## 一、本地环境准备

电脑上需要先装好以下三个东西（如果已经有了可以跳过）：

### 1. 安装 Node.js

-   去 [nodejs.org](https://nodejs.org/) 下载 **LTS 版本**，一路下一步装好。
-   验证：打开终端（cmd / PowerShell / Git Bash），输入 `node -v`，有版本号就说明成功了。

### 2. 安装 Git

-   从 [git-scm.com](https://git-scm.com/) 下载安装，同样默认设置即可。
-   验证：`git --version`

### 3. 安装 Hexo

在终端里运行：

```bash
npm install -g hexo-cli
```

**⚠️ 踩坑提醒**：安装时如果报类似 `Cannot read properties of null (reading 'matches')` 的错误，别慌——这是 npm 缓存问题。执行以下命令清除缓存并重装即可：

```bash
npm cache clean --force
npm install -g hexo-cli
```

## 二、初始化博客并本地预览

### 1. 创建一个博客文件夹并初始化

```bash
hexo init my-blog        # 文件夹名可以自己定
cd my-blog
npm install
```

### 2. 本地看看默认效果

```bash
hexo server
```

打开浏览器输入 `http://localhost:4000`，就能看到 Hexo 自带的主题（Landscape）了。

## 三、安装喜欢的主题（以 Butterfly 为例）

默认主题比较朴素，我选了漂亮的 [Butterfly](https://github.com/jerryc127/hexo-theme-butterfly) 主题。

```bash
git clone -b master https://github.com/jerryc127/hexo-theme-butterfly.git themes/butterfly
```

然后修改根目录的 `_config.yml` 文件，把 `theme: landscape` 改成 `theme: butterfly`。

**注意**：Butterfly 需要额外的渲染插件，否则会报 Pug 模板缺失的错误。一定要运行：

```bash
npm install hexo-renderer-pug hexo-renderer-stylus --save
```

装完之后再 `hexo clean && hexo generate` 就能正常显示了。

## 四、推送到 GitHub 并开启 Pages

### 1. 在 GitHub 上新建仓库

-   登录 GitHub → 右上角 **+** → **New repository**
-   **仓库名必须填 `你的用户名.github.io`**（例如我的用户名是 `molunanli`，仓库名就是 `molunanli.github.io`）
-   **不要勾选** “添加 README 文件”，保持空白

### 2. 把本地博客推到 GitHub

进入博客根目录，依次运行：

```bash
git init
git add .
git commit -m "first commit"
git remote add origin https://github.com/你的用户名/你的仓库名.git
git push -u origin main
```

**⚠️ 踩坑提醒**：如果第一次推送时遇到类似这样的错误：

```
! [rejected]        main -> main (fetch first)
error: failed to push some refs to ...
```

这是因为 GitHub 上的仓库和本地没有共同祖先（比如你在 GitHub 上创建时点了添加 README）。解决办法：

```bash
git pull origin main --allow-unrelated-histories --no-edit
git push origin main
```

这样就能合并成功并推送了。

### 3. 启用 GitHub Pages

有两种方式，我推荐用 **GitHub Actions** 全自动部署。

-   在博客仓库页面点击 **Actions** 选项卡。
-   点击 **New workflow** → **set up a workflow yourself**。
-   将下面的代码粘贴进去，然后点击 **Commit changes**。

```yaml
name: Pages

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Use Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "20"
      - name: Install Dependencies
        run: npm install
      - name: Build
        run: npm run build
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./public
  deploy:
    needs: build
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

保存后，GitHub 会自动开始构建。等一两分钟后，去仓库的 **Settings** → **Pages**，应该能看到绿框显示 “Your site is published at https://molunanli.github.io/” （替换成你自己的地址）。

至此，博客就正式上线了！🎉

## 五、开始写作

每次写新文章只需要三个命令：

```bash
hexo new "文章标题"          # 在 source/_posts/ 下生成 md 文件
# 然后用 Markdown 编辑器写内容
hexo clean && hexo generate  # 生成静态文件
git add . && git commit -m "new post" && git push  # 推送到 GitHub 自动更新
```

如果只想本地预览，用 `hexo server` 即可。

## 一些有用的经验

-   **图片管理**：把图片放在 `source/images/` 下，文章中引用 `/images/图片名.jpg`。
-   **摘要分割**：在文章正文里写上 `<!-- more -->`，前面的内容会作为首页摘要。
-   **自定义域名**：在 `source/` 下放一个 `CNAME` 文件（内容为你的域名），然后在 GitHub Pages 设置里绑定即可。
-   **标签和分类**：在文章 front-matter 里写 `tags:` 和 `categories:`，Hexo 会自动生成对应的页面。
